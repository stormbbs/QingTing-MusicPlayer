# 轻听 · 第三方音源实测报告（2026-10-21）

数据来源：GitHub `qwerwhr/musicfree-plugins`（76 个 MusicFree 插件订阅源），
经 `tools/mf_bridge` 桥接成轻听音源协议后逐个实测。

## 结论先行

| 插件 | 搜索 | 播放直链 | 可用性 |
| --- | --- | --- | --- |
| **bilibili** | ✅ | ✅ | **推荐**，唯一完整可用 |
| **哔哩哔哩**（另一版） | ✅ | ✅ | 可用，与上者功能重叠 |
| QQ音乐（非VIP） | ✅ | ❌ 多为空 | 能搜不能播，直链靠第三方中转站，常超时 |
| 汽水音乐 | ✅ | ❌ 404 | 能搜不能播 |
| 酷狗 | ❌ 403 | - | 被源站拦截 |
| 猫耳FM | ❌ 403 | - | 被源站拦截 |
| Youtube | ❌ 超时 | - | 本机网络不可达 |
| Navidrome / GitCode | ❌ | - | 需要用户自己配 `env` 变量 |

一句话：**第三方源里真正能“搜到就能播”的只有 bilibili 系**。
其它国内平台大多是「元数据能搜、播放要 VIP 或靠不稳定中转」，不如用 App 内置的酷我/网易云。

## bilibili 实测细节

- 搜「稻香」→ 20 条，首条直链解析 OK
- 搜「晴天」→ 20 条，首条直链解析 OK
- `/playlists` 榜单接口返回正常（每周必看等）
- 限制：bilibili 上的歌几乎都是 UP 主上传的合集视频，歌名带各种前缀，
  曲目本身是整段视频音频，没有正规单曲元数据；适合当“补充源”，不适合当主力。

## 怎么自己复现

```bash
cd tools/mf_bridge
npm install
# plugins/ 里已放好 bilibili.js / 哔哩哔哩.js / qq.js / 汽水qishui音乐.js
node bridge.js 18092
```

App 里「+ → 自定义协议音源」填：

- 真机同 Wi-Fi：`http://<电脑局域网IP>:18092`
- 模拟器：先 `adb reverse tcp:18092 tcp:18092`，再填 `http://127.0.0.1:18092`

## 更换/增加插件的办法

到 https://github.com/qwerwhr/musicfree-plugins 挑 `plugins.json` 里的 `url`，
下载那个 `.js` 丢进 `tools/mf_bridge/plugins/`，重启桥接器即可。
判断能不能用的最快方式：看插件导出里有没有 `search` 函数（没有的话桥接器会打印 `[skip]`）。
